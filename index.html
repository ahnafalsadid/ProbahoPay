Why Probaho

One import, one session, one payment.

Every design decision serves the same goal: get a checkout session running in minutes, not days.

01

Minimal integration

A single script import and one .init() call is enough to bring Probaho Pay into any storefront.

02

Structured sessions

Store, customer and checkout details are grouped into a clear payload — nothing ambiguous about what's required and what isn't.

03

Built on Supabase

A modern, reliable backend handles your transaction data, with success and cancel callbacks wired straight into your own URLs.

Documentation

Get a checkout running

Two steps: bring in the script, then describe the payment you want to collect.

01

Install

Import the script, then initialize it once on page load.

import { probahopay } from "";

probahopay.init();
02

Start a payment session

Build a payload describing the mode, the store, the customer and the checkout — then hand it to Probaho Pay.

const payloadData = {
    onlineMode: false,
    store: {
        merchantId: "YOUR_MERCHANT_ID",
        apiKey: "YOUR_API_KEY",
        invId: "INV-88231",
    },
    customer: {
        name: "John Doe",
        id: "abclient",
        email: "john.doe@example.com",
        address: "123 Tech Street, Suite 400",
        phone: "+8801xxxxxxxxx",
    },
    checkout: {
        amount: 2500,
        description: "A4TECH Wireless Keyboard.",
        successUrl: "http://127.0.0.1:5500/sandbox/success.html",
        cancelUrl: "http://127.0.0.1:5500/sandbox/error.html",
        metadata: null
    }
};
Parameter reference

Every field, at a glance

Red means the session won't start without it. Blue means it's there when you need it.

FieldRequirementTypeDescription
onlineModemandatoryboolSet to true or false for online mode.
store.merchantIdmandatorystrUnique merchant identifier (currentMerchantId).
store.apiKeyoptionalstrStore API key for authorization.
store.invIdmandatorystr / intUnique invoice reference ID (inv_id).
customer.namemandatorystrCustomer's full name (currentName).
customer.idoptionalstrUnique customer client ID, e.g. "abclient".
customer.emailoptionalstrCustomer email address.
customer.addressoptionalstrCustomer physical address.
customer.phonemandatorystr / intCustomer phone number.
checkout.amountmandatoryint / floatTotal payment amount (currentAmount).
checkout.descriptionoptionalstrPayment description string.
checkout.successUrlmandatorystrCallback URL on successful payment.
checkout.cancelUrlmandatorystrCallback URL on cancelled or failed payment.
checkout.metadataoptionalJSON / nullAdditional custom key-value data.
